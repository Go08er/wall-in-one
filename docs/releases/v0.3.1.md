# Wall-in-One v0.3.1: thumbnail cache fix

Pre-alpha bug-fix release on top of [0.3.0](v0.3.0.md). The companion is
unchanged: **Wall-in-One companion v0.2.1** for Noctalia 5.2 (plugin API 32)
is still the paired version, and Noctalia hosts at API 17–31 keep installing
companion v0.1.3. Wall-in-One runs on Wayland; X11 sessions are not supported.

## Fixes

- **Clearing the thumbnail cache never deletes a thumbnail made meanwhile.** Before it deletes an old cached thumbnail, the cleanup checks that the file at that name is still the one it looked at. It compared only the file's device and inode number. Some filesystems (ext4 among them) give a freed inode number straight to the next file, so a thumbnail that another running Wall-in-One wrote at that name in between could be deleted. The check now also compares the file's size and its modification and change times.
  - Only cached thumbnails in `~/.cache/wall-in-one/thumbnails` were ever affected, never your wallpapers or settings. A deleted thumbnail is made again when it's next needed.
  - This was in 0.2.0 to 0.3.0 too.
- **The test suite passes on ext4.** One test told files from folders by their size, which differs between filesystems. It now asks for files directly. Nothing in the app changed for this.

## Updating

**From 0.3.0:** update the app and refresh its service definitions as usual. There is no companion update, and nothing in your profile changes.

**From 0.2.x or 0.1.4:** read the [0.3.0 release notes](v0.3.0.md) first. Updates are one-way: going back to an older version afterwards is not supported.

## Test scope

Every check in the flake passed on the release commit: 1,607 GUI tests on a private headless Wayland compositor, the unit, golden-profile and upgrade suites, and the desktop and update VMs. The thumbnail fix was also checked on an ext4 filesystem, where the old check deleted the newer file and the new one keeps it.

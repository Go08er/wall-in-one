# Wall-in-One v0.2.2: choose the interface and GPU acceleration in Settings

Pre-alpha release. The companion is unchanged: **Wall-in-One companion
v0.2.1** for Noctalia 5.2 (plugin API 32) is still the paired version, and
Noctalia hosts at API 17–31 keep installing companion v0.1.3. The exact
companion commit is recorded in `flake.lock`.

## New

- **Choose the interface in Settings.**
  - **Where:** Settings → Appearance → Interface picks the window the app
    opens with: Classic, or New (preview). New is the redesign that was
    previously reachable only through `--ui=next`. The new interface's own
    Settings page has the same choice, so you can switch back from there.
  - **When:**
    - The choice is saved in `ui.toml` and takes effect at the next start.
    - Every start reads it: the desktop entry, `ctl open` when the app isn't
      running, and `--service`.
    - `--ui=classic` or `--ui=next` still overrides it for that start.
- **Turn GPU acceleration off.**
  - **Where:** Settings → Appearance → GPU acceleration, also on the new
    interface's Settings page.
  - **On, the default:** GTK chooses how to draw the window, exactly as before.
  - **Off:** the next start draws the window with GTK's software renderer, for
    systems where drawing on the GPU misbehaves. Wallpaper playback is not
    affected.
  - **Overrides:** a `GSK_RENDERER` you set yourself always wins. Off also
    applies to GTK programs the app starts.
  - **When it applies:** an app that's already running, a `--service` one
    included, keeps its renderer until you quit it and start it again.

## Fixes

- **The new interface's look is saved or put back.** If saving the window
  style, opacity, frost or thumbnail size fails, the window goes back to the
  saved look and says why. Before, it kept showing a look that was never
  saved, and choosing it again didn't retry the save.

## Files: what changes and how to go back

`settings.toml`, the library files and the wallpaper service's files are
unchanged.

`ui.toml` moves to version 2 only when you choose the new interface or turn
GPU acceleration off, never before. If `ui.toml` already existed, its
version 1 contents are first kept, once, as `ui.toml.v1-backup`.

0.2.0 and 0.2.1 read a version 2 `ui.toml` but don't change it, and they start
in the classic interface with GPU acceleration on. To let them edit it again,
see [going back to 0.2.1 or 0.2.0](../updating.md#going-back-to-021-or-020-after-choosing-the-new-interface-or-turning-gpu-acceleration-off).
It covers both cases:
- `ui.toml.v1-backup` exists;
- the choice created `ui.toml` in the first place.

## Updating

From 0.2.1 or 0.2.0: update the app and refresh its service definitions as
usual. There is no companion update. From 0.1.4: follow the
[update guide](../updating.md), the same as for 0.2.0.

## Test scope

Every check in the flake passed on the release commit, including:
- the packaged GUI tests, among them a fresh GTK process that starts with GPU
  acceleration on and off;
- the golden-profile and v0.1.4 downgrade suites;
- the released 0.2.0/0.2.1 `ui.toml` reader against version 2 files;
- the desktop VM and the real-package update/rollback VM, both on Noctalia
  5.2.

The VM checks also got stricter:
- **Update/rollback VM:** before each snapshot, it now waits for everything a
  GUI start launched to exit, including helpers that start their own session.
- **Desktop VM:** its service stop, kill and restart checks now run with
  systemd as the service's only lifecycle owner.

The release went through a full independent review of 0.2.1 plus the new
features, and a focused follow-up review. The last one found nothing of medium
severity or higher.

These remain outside the checks:
- physical multi-monitor behavior;
- broad GPU and driver coverage: GPU acceleration is tested only with GTK's
  software renderer;
- a live scene capture on a desktop session;
- long-running desktop use.

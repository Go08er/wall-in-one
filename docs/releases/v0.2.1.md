# Wall-in-One v0.2.1: bug fixes

Pre-alpha bug-fix release, paired with **Wall-in-One companion v0.2.1** for
Noctalia 5.2 (plugin API 32). Noctalia hosts at API 17–31 keep installing
companion v0.1.3. The exact companion commit is recorded in `flake.lock`.

0.2.1 changes no file format: everything 0.2.0 wrote is read and written the
same way. Updating from 0.1.4 works exactly as described for
[0.2.0](v0.2.0.md).

## Fixes

- **Pairings no longer freezes.** With a palette saved, searching for another
  palette and picking it froze the whole window (0.2.0 and earlier).
- **Pairings and Schedules show what was saved.** Several quick edits in a
  row (palette, mode or still on Pairings; a display's playlist or a rule's
  switch on Schedules) now each build on the last. If one fails, the control
  goes back to what is actually saved, even after a search or a page rebuild.
  Before, the page could show a choice that was never saved, or save an
  earlier combination than the one you picked.
- **The app always opens after an upgrade.** Leftover files from an upgrade
  that had already finished stopped the window and the health sync from
  starting while the wallpaper service was running.
- **Closing the window stops its background work.** Thumbnail and preview
  work owned by the classic window now stops as soon as the window closes, or
  when the app is told to quit, instead of lingering until later cleanup.
- **The wallpaper service:**
  - With mirrored displays, pressing Play after Stop when one display failed
    to start no longer leaves the other animating while the app says Stopped.
  - Every command to mpv (pause, resume, volume, mute) now has an overall
    2-second limit, so a stuck mpv can no longer freeze the service, and a
    shutdown abandons a stuck command at once.
- **No file is saved bigger than the app can read back.** Library files,
  `settings.toml`, Tidy up's archive record, saved palettes and Noctalia's
  settings file are checked before writing. An edit that would make one too
  large is refused with nothing changed, instead of leaving a file the app then
  can't open.
- **`--ui=next`:**
  - An Apply aimed at one display is refused, with a notice, if that display
    is gone or the displays are mirrored. Before, it applied the wallpaper to
    every display.
  - The Apply menus offer only displays that can be targeted on their own.
- **Documentation:**
  - The README describes the new interface's live playback controls and their
    scope.
  - The settings guide says when `ui.toml` is written on close.
  - The library guide lists each file's size limit.

## Companion 0.2.1

- A one-display menu action ("Play on eDP-2 only", or a display's own menu)
  whose display was unplugged, or that became meaningless after a switch to
  mirrored mode, now sends nothing and says so. Before, it acted on every
  display. A global menu stays global.
- Documentation:
  - The companion starts the wallpaper service directly only with an
    executable override, or on a system without `systemctl`.
  - The preview has 13 fixtures.

## Updating

From 0.2.0: update the app and refresh its service definitions as usual, then
update the companion through your Noctalia plugin source. From 0.1.4: follow
the [update guide](../updating.md), the same as for 0.2.0.

## Test scope

Every check in the flake passed on the release commit, including:
- the packaged GUI tests;
- the golden-profile and v0.1.4 downgrade suites;
- the desktop VM and the real-package update/rollback VM, both on Noctalia 5.2.

Each fix has a regression test that reproduces the original failure and fails
on 0.2.0. The release candidate went through a full independent review of
0.2.0 and three focused follow-up reviews. The last one found nothing of
medium severity or higher.

Physical multi-monitor behavior, broad GPU coverage, a live scene capture on a
desktop session, and long-running desktop use remain outside these checks.

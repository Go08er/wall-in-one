# Wall-in-One v0.4.1: every kind of Wallpaper Engine item, renderer settings, web wallpapers by choice

Pre-alpha release. The paired companion is still **Wall-in-One companion
v0.3.0** for Noctalia 5.2 and later (plugin API 32); it doesn't show this
release's new status yet ([Companion](#companion-v030)). Wall-in-One runs on
Wayland; X11 sessions are not supported.

**Web wallpapers are off until you allow them.** 0.4.1 lists Wallpaper
Engine's web wallpapers for the first time, and plays them only with **Allow
web wallpapers** turned on in Settings → Library. A web wallpaper is a page
whose JavaScript runs in linux-wallpaperengine's built-in browser, an older
Chromium with web security and site isolation off, so the page can reach web
services on your computer and its network and send data out. Read what the
setting says before you turn it on. Executable ("application") wallpapers are
never run, whatever the setting.

## Every kind of Wallpaper Engine item is listed

- **Every kind is listed.** Up to 0.4.0 only videos and scenes showed up;
  web wallpapers, presets and every other kind were left out without a
  word. Every item that isn't a video is now listed under Scenes,
  with its own type beside it ("Scene · web", "Scene · preset") and, when it
  can't play, why. A note there says how many need runtimes
  linux-wallpaperengine doesn't support. See
  [Wallpaper Engine items](../wallpaper-engine.md).
- **Presets play.** A preset (a wallpaper's saved Wallpaper Engine settings)
  plays its base wallpaper with the preset's settings passed to
  linux-wallpaperengine. The service has to be this release's: an older one
  still running is given everything but the presets, and the app says so
  once.
- **Executable ("application") wallpapers are never run**, even where they
  would work, and neither is a preset of one. They are listed as unsupported.
- **Check Wallpaper Engine for new wallpapers:** a button in Scenes and
  Videos (classic: "Videos and scenes") runs the library rescan (F5), for
  what Steam added since.

## Renderer settings

- **mpvpaper's and linux-wallpaperengine's settings in the app:** the global
  defaults in Settings, and per-wallpaper overrides in each wallpaper's own
  settings (the classic pairing editor, the new interface's details), each
  with its own reset. A scene's own Wallpaper Engine properties are there too,
  one control each. See [Renderer settings](../renderer-settings.md), which
  also lists [what is left out, and why](../renderer-settings.md#left-out-and-why).
- **A typed allowlist.** Every setting is a typed value in a closed range.
  There is no free-form option, so none can run a program or read a file.
- **A setting changed just before you close the window or quit is saved**,
  a per-wallpaper number or a global one.

## Web wallpapers, while they are off

- **Nothing plays a web page by any route:** play, toggle, Resume, a reload, a
  restart, schedules, rotation, either display mode.
- **The service checks each item's own type when it starts it**, so a
  Workshop update that turns a scene into a web page is caught too.
- **Nothing is previewed from a web wallpaper's files.** The app opens only
  its `project.json`, and the tile shows a placeholder. Each Workshop item's
  `project.json` is read again just before a thumbnail or a still is made,
  and just before linux-wallpaperengine is given its id, so a Steam update
  since the last scan is caught.
- **In a playlist,** a web wallpaper is skipped and the rest plays. A
  playlist left with nothing is set aside, so the display follows the
  schedule, then the default playlist, then All media. A display plays
  nothing only when nothing in the library can play, and then it says
  "Nothing to play: web wallpapers are off". Noctalia keeps the last still it
  was given.
- **If turning it off can't reach the service** (a failed update, a refused
  reload, a quit at a bad moment), the app stops the page, writes safe
  settings to disk, and tells you what to do. An outdated service is told to
  quit, and its next start refuses settings that allow web pages.

## Wallpapers the service can't start

- **Skipped, not marked broken.** A web page while web wallpapers are off, a
  scene on a second Steam library (linux-wallpaperengine looks only in your
  home folder's Steam installations), an unreadable project file: the
  service skips it for the next entry, then the default playlist, then All
  media. It is never marked broken for good.
- **Said where you look.** The status lists what was refused, and the
  library marks those items "Can't play here". When a stand-in playlist plays
  for the one you picked, both windows say so, and the selectors stay on your
  pick.

## Quitting from a terminal (Ctrl-C)

- **Your changes aren't lost to Ctrl-C any more.** In 0.4.0 a Ctrl-C dropped
  playlist, pairing and schedule edits still waiting behind a save. Now, with
  changes of yours waiting, the first Ctrl-C holds them and counts down:

      Saving 2 changes before quitting in 5… press Ctrl-C again to quit immediately without them, or any other key to cancel quitting.

  At zero they are saved and the app quits. Ctrl-C again quits without them.
  Any other key cancels the quit ("Quitting cancelled."), and the app carries
  on and saves them. Keys the terminal acts on itself don't count: Ctrl-Z
  suspends the app, Ctrl-\\ ends it without saving, Ctrl-S and Ctrl-Q pause
  and resume its output.
- **With nothing of yours waiting,** Ctrl-C quits at once, as before.
- **Turning web wallpapers off is never dropped**, whichever Ctrl-C quits, and
  a save already being written always finishes. The terminal is put back on
  every way out but SIGKILL.
- **Other ways of stopping the app are taken as meant.** Closing the window,
  `wall-in-one ctl quit` and Ctrl-C (any SIGINT) save what is waiting. Any
  other stop (SIGTERM, SIGHUP, Ctrl-\\'s SIGQUIT, closing the terminal, logging
  out, the display going away) saves nothing and ends the app at once, as it
  already did. So a switch to web wallpapers off that is stopped that way
  before it reaches the service leaves a page playing until the app or the
  service next starts, and the service's start check then refuses it.
- See [Quitting from a terminal](../../README.md#quitting-from-a-terminal).

## Status replies

- **New fields** for clients such as the companion: `nothing_to_play` (and a
  display's `entry_name` then), `stand_in_for`, `refused` and
  `refused_omitted`, `allow_web_wallpapers`, and flags for what a reply left
  out to fit. See [Runtime configuration](../runtime-config.md).
- **The size limit is exactly 0.4.0's**, so a configuration 0.4.0 loaded
  still loads. When a reply is too big, the new fields give way first, and a
  flag says so. A reply never carries less than 0.4.0's did.

## Companion v0.3.0

The companion is unchanged. Nothing breaks, but it reads none of the new
status fields yet:

- a stand-in playlist shows as your pick;
- refused items aren't shown;
- with nothing to play, it still says "Playing", with Pause and Next active;
- when a reply left an error out to fit, it reads the empty error as none.

## Known limits

None of these can start or show a web page, or run an executable. They are
described in [Runtime configuration](../runtime-config.md) and
[Wallpaper Engine items](../wallpaper-engine.md).

- **Independent displays:** a display already showing a wallpaper that
  another display finds it can't play, or marks broken, keeps it until its own
  next change; when that change fails, its status can wrongly say the
  previous wallpaper was restored; and an independent display with nothing
  left and no stand-in plays nothing but still reports the error.
- **Mirrored startup with assignments:** a display with nothing left and no
  stand-in, while another still plays, can keep a video under "Nothing to
  play" until the next apply of every display.
- **From 0.4.0:** at a schedule change to the default playlist, a display
  already showing that playlist restarts once.
- **A library folder of yours that covers Steam's Workshop folder** lists the
  pictures and videos in a web wallpaper's folder as your own files, and
  previews them like any others.
- **Until the next scan:** a picture paired with a Workshop video stays its
  still, and gives its colours, if Steam turns that folder into a web
  wallpaper's; a preset that now names another base is judged by the base
  the scan found.

## Updating

- **From 0.4.0:**
  1. Update the app and its service definitions.
  2. Restart the wallpaper service. Until you do, the one still running gets
     no presets.
  3. Keep the companion at v0.3.0.
- **From 0.3.x:** read the [0.4.0 release notes](v0.4.0.md) first; the
  renderers have to be installed before the update.
- **Updates are one-way:** going back to an older version afterwards is not
  supported. 0.4.0's Settings go read-only once a renderer setting is changed,
  and its service refuses a configuration that has presets.

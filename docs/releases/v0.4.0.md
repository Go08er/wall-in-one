# Wall-in-One v0.4.0: any compositor, renderers installed separately

Pre-alpha release. The paired companion is **Wall-in-One companion v0.3.0**
for Noctalia 5.2 and later (plugin API 32). Noctalia hosts at API 17–31 keep
installing companion v0.1.3. The exact companion commit is recorded in
`flake.lock`. Wall-in-One runs on Wayland; X11 sessions are not supported.

**Before you update from 0.3:** the package no longer contains the wallpaper
renderers. Install them first, as
[Updating](../updating.md#from-03-to-04-install-the-renderers-first)
describes. If you don't, videos and scenes show their stills until you do.

## Any compositor that Noctalia 5 supports

- **No niri needed.** The wallpaper service finds displays through the
  standard Wayland protocols: `wl_output`, xdg-output, and
  wlr-output-management where the compositor offers it. The window falls back
  to GTK's monitors when the service isn't running. Nothing calls `niri` any
  more.
- **Tested on niri and on Sway**, both in VMs. Hyprland is expected to work
  but was not tested.
- **Sway and Hyprland users:** the service needs your session's
  `WAYLAND_DISPLAY`. See
  [The service needs your session's display](../installing.md#the-service-needs-your-sessions-display)
  for the one line to add.
- **A display switched off in the compositor**, rather than unplugged, now
  counts as disconnected (`connected: false`) and is handled exactly like an
  unplugged one: its renderer stops, and its assignment comes back when it is
  switched on again. That is while another display is still on: with every
  display switched off, the service keeps the displays it last saw and
  reports a display-discovery error until one is switched on. Under 0.3.x,
  which asked niri, it stayed `connected: true`.
- **niri's window rules** are now an optional example in
  [Compositor window rules](../compositor-window-rules.md).

## Renderers are installed separately

- **Not in the package any more:** mpvpaper (video wallpapers) and
  linux-wallpaperengine (Wallpaper Engine scenes). FFmpeg, for thumbnails and
  stills, still is.
- **On NixOS and home-manager,** the flake's new module installs both:
  `programs.wall-in-one.enable = true`. Set
  `programs.wall-in-one.manualWallpaperInstalls = true` to install them
  yourself instead. See [Installing](../installing.md).
- **Paths that survive cleanup.** The wallpaper configuration now names a
  renderer where it is installed, for example your profile's `bin`, rather
  than its exact Nix store path. Updating a renderer no longer rewrites the
  configuration, and a profile update followed by garbage collection no longer
  leaves it pointing at nothing.
- **A missing renderer is not a broken wallpaper.** A display whose renderer
  is missing shows the wallpaper's still. The service reports the renderer as
  missing, and nothing is skipped or saved against the wallpaper. The same
  applies to a renderer that is installed but can't run, for example after a
  library update broke it.

## The app says what is missing

- **A notice in the window** when something it needs is missing:
  - the wallpaper service;
  - Noctalia;
  - every renderer, but only when your library has videos or scenes.
- **Settings → Setup** lists everything, including optional things such as the
  companion plugin. Each item comes with how to install it for your kind of
  install.
- **Check Again** compiles the configuration again and has the service retry,
  after you install something.
- **`wall-in-one --setup-status`** says the same from a terminal. It exits 0
  when nothing required is missing, 1 when something is, and 2 when it couldn't
  tell.

## Install kind

- **Both programs report how they were built.** `wall-in-one --version` and
  `wall-in-one-service --version` print `install kind: nix`, `system` or
  `source` on their second line, and the service's status has `install_kind`.
- **Companion 0.3.0** shows it, and refuses to start or command anything while
  both a Nix install and a system package are present.

## Arch Linux

- **A PKGBUILD that builds from source** is in `packaging/arch`. It installs
  the app, the service and the user units.
- **Not on the AUR yet.** Until it is, build it from a checkout with
  `packaging/arch/local-build.sh`; see [Packaging](../packaging.md).

## Fixes

- **Per-display mode, display switched off:** a display with its own
  assignment that is switched off now keeps its row in the status after a
  reload, as it already did after a start.
- **`cycle off`** now holds when the display mode changes, and for displays
  that are switched off or connect later. Before, a mode change silently
  dropped it.
- **A compositor that stops answering** can no longer stall the wallpaper
  service. Each display query has a time limit, and stopping the service
  always works.
- **Saving while an older service still runs:** a save refused by the service
  from before the update now says to restart the wallpaper service.
- **A thumbnail stuck on loading:** changing a wallpaper's still while its
  thumbnail was being made could leave the new thumbnail loading until the
  window was reopened.
- **The Store's automatic quality** is now called **Automatic (as listed)**:
  it follows the listing's HD or 4K badge, and asks the wallpaper's page for
  4K, then HD, only when the listing has none. It was called "Best
  available", which promised more than it did.

## Companion v0.3.0

- **Install detection:**
  - it tells a Nix install from a system package, and both at once is an
    error;
  - it shows the install kind the service reports.
- **Starting the service:**
  - with no user unit, it starts the service directly;
  - it uses the install it found, even when that is not on Noctalia's `PATH`.
- **Restarting:** it says how to restart the service when the running one is
  from the other install.

## Updating

- **From 0.3.x:**
  1. Install the renderers first
     ([Updating](../updating.md#from-03-to-04-install-the-renderers-first)).
  2. Update the app and its service definitions.
  3. Restart the wallpaper service.
  4. Update the companion to v0.3.0.
- **From 0.2.x or 0.1.4:** read the [0.3.0 release notes](v0.3.0.md) first.
- **Updates are one-way:** going back to an older version afterwards is not
  supported.

## Test scope

- **Release commit:** every check in the flake passed. That covers:
  - 1,644 GUI tests on a private headless Wayland compositor;
  - the unit, golden-profile and upgrade suites;
  - the wallpaper service's own tests;
  - the desktop VMs on niri and on Sway, the Sway one with switched-off and
    re-enabled displays.
- **Arch:** the package was built, tested and installed in an Arch Linux
  container in CI.
- **Not covered:** non-NixOS hardware and Hyprland.

# Wall-in-One v0.1.4

Pre-alpha maintenance release, paired with **Wall-in-One companion v0.1.3**
for Noctalia 5. The exact companion commit is recorded in `flake.lock`.

## Changes

- Refresh GTK theme variables when Noctalia's palette changes, without
  restarting the app.
- Refresh tested dependencies and packaging while retaining the existing
  Python/GTK app and Rust runtime.
- Distinguish temporarily unavailable runtime status from confirmed absence.
  `wall-in-one ctl status` exits 75 on its deadline; a missing listener still
  exits 3. Timed-out playback changes remain errors and are not replayed.
- The matching companion tolerates temporary status delays during startup,
  clearly marks its last good view as stale when needed, and backs off failed
  health-persistence attempts without claiming the runtime has stopped.
- Add regression coverage for status deadlines and a disposable desktop VM
  scenario that delays a real cold start, then verifies successful startup
  with one runtime process.

## Updating

Follow the [update guide](../updating.md): finish pending work, close the app,
temporarily disable automatic launchers, stop the service and health helpers,
and back up config/state before changing packages. Update the app, refresh its
service definitions, complete the normal restart, then enable the matching
companion through the owner of your Noctalia plugin source.

This patch introduces no new configuration format or reset. Existing migration
and validation safeguards remain in place. Saved library locations, pairings,
playlists, and schedules are preserved; temporary playback choices and position
may reset on restart. Invalid or newer unsupported configuration must be
repaired through the app's recovery path, not deleted to force startup.

## Test scope

Coverage includes Python/Rust checks, packaging and version consistency,
companion Luau behavior, and the disposable desktop VM's migration, recovery,
and delayed-start scenarios. Physical multi-monitor behavior, actual GPU
rendering, and long-running desktop use remain outside these checks. See the
[VM limitations](../virtual-machine.md#honest-limits).

# Wall-in-One v0.2.0: forward-compatible files, scene stills, Tidy up

Pre-alpha release, paired with **Wall-in-One companion v0.2.0** for Noctalia
5.2 (plugin API 32). Noctalia hosts at API 17–31 keep installing companion
v0.1.3 from the same catalog. The exact companion commit is recorded in
`flake.lock`.

0.2.0 updates 0.1.4 directly: there is no 0.1.5. Nothing is reset or
converted on update. 0.2.0 reads every 0.1.4 file as it is.

## Scene stills, for the first time

- Scene stills can now be captured. Since 0.1.0 every real scene capture,
  automatic or **Regenerate**, was refused: linux-wallpaperengine picks its
  screenshot format from the file extension, and the app handed it a path
  without one. The engine now gets a `.png` name inside the app's own folder,
  and only the file the app created is published.
- Automatic recapture judges a scene still against the measured display only.
  It recaptures a still smaller than the display in both directions, never
  because of its shape alone, so plugging in a 16:9 monitor no longer
  recaptures every scene. With no display measured, no scene is touched.
- Scene captures run on the still worker, not the window's main loop. When a
  capture ends, any process the engine started is stopped too.
- A recaptured still is saved readable only by you (0600).

## Nothing written while idle, and no leftovers

- Without linux-wallpaperengine or a measured display, no scene still is
  attempted and nothing is written. Before, each attempt left an empty folder
  and a 0-byte file under `Automatic Stills/.wall-in-one-retained`.
- A failed video still (ffmpeg missing, an unreadable video, a timeout) leaves
  nothing behind.
- Opening or idling writes only `runtime.toml` (on first start), a
  `pairings.json` health marker after a reported failure, and automatic stills
  in the library's `Wall-in-One/Automatic Stills/`.
- Startup rebuilding of old automatic stills stops after 12 seconds and
  finishes on a later start, so a slow decoder can't hold up the service or the
  window.
- Background jobs (thumbnails, stills, Noctalia commands) stop every process
  they started when they finish, time out, are canceled or fail.

## Files from a newer release open read-only

- Favorites, pairings, playlists, schedules, display assignments and the
  pending-removals journal saved by a newer release are shown as far as 0.2.0
  understands them, and never rewritten or moved aside. Edits are refused with
  the reason, and the wallpaper service keeps its last good configuration.
- Fields this release doesn't know are kept through every save.
- A `settings.toml` key this release doesn't know makes Settings read-only
  instead of failing; the service still starts on the keys it knows.
  `settings.toml` keeps 0.1.4's keys: window preferences go in the new
  `ui.toml`.
- Remove and Move to Trash are refused before anything is touched when a
  record they need to update can't be saved.
- A setting that was saved but couldn't be confirmed on disk is kept, with a
  message saying so, instead of being reported as not saved.

## Rule names, and groundwork for per-playlist rotation

- Schedule rules can have names: `wall-in-one ctl schedule-name <rule-id>
  [name]`. The Schedules page shows them.
- The service and the file formats now support a playlist's own interval and
  shuffle, and a display whose own playlist beats global rules. There is no
  page to set these yet; that comes with the new interface's Playlists and
  Displays pages.
- A file moves to a new version only when one of these is first used, after a
  one-time backup: `schedules.json` version 3 (`schedules.json.v2-backup`),
  `playlists.json` and `displays.json` version 2 (`.v1-backup`). A profile that
  doesn't use them keeps every file in 0.1.4's formats.
- The playlist and display settings reach the service through a new
  `runtime-overrides.toml`. `runtime.toml` keeps 0.1.4's format, so an older
  service still starts and simply ignores the new file.

## Status timing

- The service's status now says when each display's schedule next changes and
  when it next rotates. Both are exact across daylight-saving changes, including
  half-hour zones and the hour that repeats in autumn.
- The companion and the new interface show this as "until 18:00" and
  "Next in 12 min".

## Tidy up

- Settings has a new **Tidy up** section, offered once on the first launch
  after the update with a dismissible card. Every action shows a preview first,
  keeps a backup or archive, and can be undone; nothing runs without a click.
  - Archive the leftovers of earlier updates and deletions into one dated
    folder in the config directory. Only entries proven unused are moved;
    nothing is deleted.
  - Point Noctalia at the current palette template name. The old template is
    archived only after Noctalia confirms it reloaded.
  - Remove the retired plugin's leftover settings from Noctalia, keeping every
    key the companion uses.
  - Show the thumbnail cache's size and clear it (this one can't be undone, and
    the preview says so).

## The new interface, behind `--ui=next`

- `wall-in-one --ui=next` opens the redesigned window over your real library,
  stores and service. The classic window stays the default.
- It is an early preview: the Library grid with its details pane, Apply,
  favorites, and a player bar with play/pause, next, previous, random, shuffle,
  cycle and Resume schedule. Store, Playlists, Schedule, Displays and Settings
  point back to the classic window for now.
- Its window style, opacity, frost and thumbnail size live in `ui.toml`,
  written only when you change one of them.

## Rolling back to 0.1.4

0.2.0 isn't designed to be rolled back. To go back to 0.1.4, close the app,
stop the service and run `wall-in-one-rollback`. With no arguments it shows
what it would drop (rule names, per-playlist intervals and shuffle, display
opt-ins); `--apply` backs up and then rewrites `playlists.json`,
`schedules.json` and `displays.json` in 0.1.4's formats, keeping every
playlist, entry, rule and assignment, and removes `runtime-overrides.toml`. It
prints the commands that restore its backup. It refuses while the app or
service runs, while another Wall-in-One operation holds the profile, if a file
changes while it runs, and on files from a release newer than 0.2.0.

Without the tool, 0.1.4's app shows an empty library and saves nothing until
you update again, but nothing is lost and the wallpaper keeps running. 0.1.4
ignores `ui.toml` and `tidy-archive/`. See the [update guide](../updating.md).

## Updating

Follow the [update guide](../updating.md): finish pending work, close the app,
temporarily disable automatic launchers, stop the service and health helpers,
and back up config and state before changing packages. Update the app first,
refresh its service definitions and restart, then update the companion through
your Noctalia plugin source.

## Test scope

Every check in the flake passed on the release commit: the Python and Rust
suites, the packaged GUI tests, the golden-profile suite built from a sanitized
copy of a real profile, the downgrade suite against the shipped v0.1.4 source,
type and lint checks, the companion contract, the runtime socket fallback, the
service memory budget, the desktop VM (now on Noctalia 5.2, which the
companion needs), and a new real-package VM test that
installs v0.1.4, updates to 0.2.0, uses the new features, rolls back (with and
without `wall-in-one-rollback`) and updates again. The release candidate went
through several independent code-review passes; every finding was fixed before
release.

Physical multi-monitor behavior, broad GPU coverage, a live scene capture on a
desktop session, and long-running desktop use remain outside these checks. A
scene capture runs the engine in window mode and may briefly show a window.
See the [VM limitations](../virtual-machine.md#honest-limits).

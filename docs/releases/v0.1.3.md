# Wall-in-One v0.1.3

Pre-alpha release, paired with **Wall-in-One companion v0.1.2** for Noctalia 5.

## Changes

- Optional **Stop animations on battery** policy: show stills on battery and
  resume motion when plugged in, respecting playback settings.
- Clearer Library, Store, Settings, playlist and schedule controls, with live
  Noctalia palette updates.
- Safer startup and ordinary updates: preserve saved paths and data, validate
  runtime configuration before Rust starts, and refuse incompatible settings
  changes before writing them.
- Configuration recovery stays available when settings are invalid. Open the
  file in your editor, save a correction and retry without resetting the profile
  or requiring the wallpaper daemon to run.
- The matching companion prepares and validates direct runtime startup, reports
  installed-service failures without bypassing them, and shows battery status.

## Updating

Follow the [update guide](../updating.md). Finish pending work, close the app,
temporarily disable the companion and other automatic launchers, stop the
service and health helpers, and back up config/state before changing packages.
Update the app first, refresh the service definitions through the installation
that owns them, then restart and enable the matching companion.

Saved library folders, pairings, playlists and schedules remain in place.
Temporary playback choices and the current position may reset to saved settings
on restart. This is a normal restart, not a seamless handover.

Keep battery control off until the running daemon supports it. An older app may
reject settings with that option enabled; package rollback does not downgrade
data. Keep the compatible newer package available for repair. Do not delete
settings or migration journals to force a fresh start.

## Test scope

The release checks cover Python/Rust, native GTK, packaging, migration,
companion controls, memory/CPU limits and disposable desktop/old-to-new VMs.
The recovery VM opens a real editor, saves a repair and reaches Settings in the
same process while the daemon stays stopped, checking original paths and data.

Physical multi-monitor behavior, actual GPU video/scene rendering and long-use
desktop validation remain outside these automated checks. See the
[VM limitations](../virtual-machine.md#honest-limits). This remains pre-alpha
software, not a claim of unattended daily-driver reliability.
